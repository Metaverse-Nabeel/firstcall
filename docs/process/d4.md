# D4 — evaluation

Running total: **27.0h / 40**.

## Built
- 60-case set, labels before prose, realizer blind to every label field.
- `eval/scoring.ts` + `eval/run.ts`: E1–E8, RED gates, ablation, τ sweep, baselines.

## Decided
- **Two leakage denominators, reported separately.** Unsupervised leakage is structurally
  zero because GATE blocks every money route — reported to *prove* the property, not as an
  achievement. Recommended leakage is what the ablation actually moves and what leaks in
  practice once a busy coordinator starts accepting recommendations. Collapsing them into
  one headline number would have been the single easiest way to overstate these results.
- **Keyword baseline implemented as a null LLM client**, which forces the existing lexicon
  and template fallbacks. No parallel implementation to maintain, and it tests the real
  fallback path rather than a mock of it.
- **τ\* = the *smallest* τ satisfying the constraints**, i.e. the most autonomy that still
  holds leakage ≤ 0.5%, safety FN = 0 and review load ≤ 35%. Picking the largest would look
  safer and buy nothing.

## Found
- **The binding free-tier constraint is requests per MINUTE, not per day.** The plan assumed
  per-day. A 1.1s interval (~54 rpm) exhausted quota after 49 calls with token usage nowhere
  near any limit. Raised to 4.5s (~13 rpm) and taught the backoff to honour the server's own
  `retryDelay`. This is exactly the failure the fixture cache exists to absorb: the re-run
  after the fix cost 11 calls, not 60.
- Replay mode correctly hard-failed on a cache miss before any fixtures for EXTRACT existed.
  Unpleasant at the time, and the right behaviour: a silent fallback to the network would
  have made the offline-reproducibility claim false while appearing to work.
