  `pipeline.ts`, `decide-llm.ts` (ablation only).

- Three UI screens on server actions.

## Decided
- **Routing is an ordered array, not nested conditionals.** It has to be unit-testable and
  printable as a confusion matrix; nested ifs are neither.
- **Money routes are blocked in GATE as well as in the routing table.** Redundant today, but
  it means a future table edit cannot quietly introduce autonomous spending. Defence in depth
  on the one property the product exists to guarantee.
- **Groundedness allow-list is built from the structured payload, never the report text.**
  Otherwise an injected "replacement cost $9,999" launders itself into the work order via
  the summary — the injection would pass *through* the checker rather than be caught by it.
- **W-07 (boundary) evaluated before W-08 (PM) and W-05 (expiry).** Boundary gates to a
  human, which is the cheap-to-be-wrong outcome, so it must win.
- **In-memory result store, no database.** Nothing in 40 hours justifies one, and a fake
  persistence layer in a demo is the easiest lie to tell.

## Found
- The exhaustive routing sweep (severity × safety × cost × symptoms) caught that
  `EMERGENCY_DISPATCH` is reachable from a COVERED asset via R-01. That is **correct** — a
  gas leak is attended first and billed afterwards — but it had to be asserted deliberately
  rather than discovered in production. The test now encodes *why* it is allowed.
