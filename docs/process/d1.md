Running total: **3.2h / 40**. Bullets only, 30-min cap. Raw material for the Day 5 edit pass.

## Built

  window by construction, which is the cleanest possible prior-work disclosure.
- Two-tree separation live: `MUST-work/` created as a **sibling**, so `git add .` cannot

## Decided

- **Model pinned empirically, not from docs.** `gemini-3.5-flash-lite` at
  `thinkingLevel: "low"`. The model list advertises 41 models; most 404 for a new
  free-tier key. Pin only what has actually returned 200.
- **Registry over-samples the warranty boundary to 18.6%** (vs. ~3% realistic). The ±30d
  band is where money leaks and where a model is least reliable, so the case generator
  needs a deep enough pool to sample from without reusing the same handful of assets.
  This skew is deliberate and must be declared in the write-up — an unflagged skewed
  sample reads as an accident.
- **2–4 same-class units per store.** 75% of assets now sit in an ambiguous class. A store
  with one fryer makes RETRIEVE a no-op and the ambiguity metric a lie; ambiguity has to
  be manufactured on purpose.
- **Vendors cover ~88% of store/type pairs, not 100%.** An uncovered pair has no SLA and
  must escalate under R-04. A missing vendor is missing data, not a reason to substitute.
- **No money-spending route is ever autonomous.** `VENDOR_DISPATCH` and
  `EMERGENCY_DISPATCH` require a human at every confidence. No threshold unlocks them.
  This is asymmetric authority expressed as a table rather than a paragraph.
- `pmLogComplete: null` (log missing, W-09 → `UNKNOWN_MISSING_DATA`) is kept distinct from
  `false` (log known incomplete, W-08 → `VOIDED_NO_PM`). Collapsing them would hide a
  missing-data failure inside a coverage verdict.

## Found

- Pre-commit hook initially used `AIza[…]{35}`, which **failed to block a 38-char
  near-miss key** during its own test. Loosened to `{30,}`. A secret scanner that only
  catches perfectly-formed keys is worse than none, because it is trusted.
- `create-next-app` refuses a directory named `MUST` (npm forbids capitals in package
  names). Hand-rolled the scaffold instead — fewer moving parts, and the agent core stays
  free of Next-specific imports so the CLI harness can import the identical `runPipeline`.
- `esbuild`/`unrs-resolver` postinstall scripts left unapproved under npm 11; `tsx` runs
  anyway via platform-specific optional deps. Left unapproved rather than widening the
  supply-chain surface for tooling that already works.
